# A2: мейкер-ліквідність на HL після свіпу кита: специфікація v1 (для paper, потім micro-live)

Статус: **weak**. Історичний край з реалістичним виходом на HL: +0.20..+0.27% на філ, нижня межа CI90 на TEST ≈ 0.
Цей документ фіксує правило ДО paper-перевірки. Під час paper параметри не змінюються.

## 1. Дані та події

| Потік | Джерело | Навіщо |
|---|---|---|
| HL `trades` по монетах | `wss://api.hyperliquid.xyz/ws`, `{"type":"trades","coin":C}` | тригер (адреса тейкера з `users`) і правило філу |
| HL `l2Book` повна точність | те саме, `{"type":"l2Book","coin":C}` | touch, прогін IOC-виходу, перевірка ALO, basis |
| HL `l2Book` з `nSigFigs=3` | окреме WS-з'єднання | глибина в межах 1% (depth1) і розмір у смузі 0.8–1.2% |
| Binance `bookTicker` | `wss://fstream.binance.com/stream?streams=<sym>@bookTicker/...` | fair |
| Список гаманців | `a2_wallets.txt` (429 адрес із whale_txs) | «трекнутий» тейкер |
| Fallback-глибина | `a2_depth.json` (медіана depth_usd бота за 3 дні) | якщо агрегованого стакану ще нема |

Тейкер угоди HL: `side=="B"` → покупець `users[0]`, інакше продавець `users[1]`.
Свіп: це всі принти з однаковими (coin, hash, taker). Свіп закривається через 300 мс без нових принтів.

## 2. Формули

- `basis_c`: ковзна медіана `(HL_mid / BN_mid − 1)` за 60 хв. Семпл береться 1 раз на секунду, лише коли BN-тік свіжіший за 2 с. Останні 5 с у медіану не входять. Потрібно ≥ 30 семплів.
- `fair_c = BN_mid · (1 + basis_c)`. Якщо BN-тік старший за 5 с, fair = None: не армимо, а відкриту позицію закриваємо IOC.
- `depth1_c = 0.69 · (USD бідів у межах 1% + USD асків у межах 1%)` на книзі nSigFigs=3. Коефіцієнт 0.69 калібрує до шкали `depth_usd` бота (медіана відношення по 41 монеті). Fallback: `a2_depth.json`.
- `td = sweep_usd / depth1_c`.
- `wd`: напрям тейкера: +1 купує, −1 продає. Наш бік `side = −wd` (кит продає → ми LONG).
- Рівень входу: `L = fair · (1 − side · X/100)`.
- Рівень мейкер-виходу: `A = fair · (1 − side · d/100)`.

## 3. Правило (параметри v1 заморожено)

| Параметр | Значення | Коментар |
|---|---|---|
| тригер | свіп трекнутого гаманця з `td ≥ 0.3` | open/close у WS невідомі. Історично включення відкриттів і liq нічого не змінює (+0.53/+0.52) |
| X | **1.0%** (первинний); тіньові 1.25 і 0.75 | X=1.25 кращий на обох половинах, але це найкращий варіант на DISC (walk-forward: DISC +0.58 → TEST +0.36, n=26) |
| вікно армування W | 60 с | 30/120 с дають майже те саме |
| вхід | **ALO** (post-only) лімітка на рівні L | перепег, коли fair зрушив > 0.05%. Одна заявка на (coin, напрям) |
| re-arm | після філу: не раніше ніж через 60 с | |
| розмір | $2k на заявку (paper); micro-live $1k | місткість за рівнем: p10 $4.3k, медіана $27.6k |
| вихід 1 | одразу після першого філу ставимо **ALO** на A = fair ∓ 0.1% з перепегом | |
| вихід 2 | якщо touch HL уже кращий за A → **IOC** по touch | |
| вихід 3 | через H = 60 с після першого філу: **IOC** на решту, прогін по книзі | H=120 на історії не гірше, але v1 = 60 |
| аварійний стоп | **IOC**, коли touch HL на 3% гірший за вхід або fair застарів > 5 с | стопи 0.75–2% у вікні 60 с погіршують середнє (див. KEY_NUMBERS) |
| сторони | LONG: основна; SHORT армимо, але аналізуємо окремо | історично 71 LONG / 5 SHORT, SHORT −0.17 |

**Правило філу (консервативна черга).** Нашу заявку виконує лише принт тієї ж монети з тим самим напрямом тейкера і ціною **строго за L** (для біду px < L). Зараховується лише USD таких принтів. Принт рівно на L нас не виконує: вважаємо, що ми останні в черзі. У paper враховуються всі тейкери, в історії: лише трекнуті, тож історія дає нижню межу кількості філів.

**Правило мейкер-виходу.** Аналогічно: зараховуються лише принти протилежного напрямку строго через A і лише їхній USD.

## 4. Ризик-ліміти

- Не більше 3 одночасних позицій (історичний максимум: 3). Не більше 1 позиції на монету і напрям.
- Денний стоп: реалізований P&L < −$150 (paper, $2k) → до кінця доби UTC не армимо.
- Капітал на HL (cross, 5x): $1k/заявку → ~$1.2k; $2k → ~$2.4k; $5k → ~$6k (з 2x запасом).
- Не армимо, якщо: немає fair або basis (< 30 семплів); ALO було б відхилене (L перетинає протилежний touch); монети немає в `a2_coins.json`.
- Kill-критерії paper, заздалегідь: при n = 30 закритих LONG-філів середній net ≤ 0 → стоп. При n ≥ 60 верх CI90 (кластер за гаманцями) < +0.10% → стоп. Частота < 1.5 філа на день → стоп. Частка виходів, закритих мейкером, < 25% → переоцінити.

## 5. Логування (JSON lines, одне поле `ev` на подію)

| ev | Поля |
|---|---|
| `start` | параметри, монети, кількість гаманців |
| `arm` | id, X, coin, side, L, fair, basis, depth1, trig{taker, usd, td, exc_pl, hash, tracked}, shadow, visible_at_L_usd, book_span_pct, agg_bid_1/ask_1 |
| `skip_trigger` | why ∈ {no_fair, no_depth, max_pos, daily_loss} |
| `alo_reject` | id, L |
| `fill` | id, X, coin, side, L, print_px, usd (зарахована частина), filled, size, wait_s, fair |
| `expire` | id, filled, repegs |
| `exit_maker` | id, A, print_px, usd, remaining |
| `exit_taker` | why ∈ {hold, stop, stale_fair, touch_better_than_A, end_of_session}, usd, vwap_rel, touch, fair |
| `close` | net_usd, net_pct, gross_usd, fees_usd, maker_exit_share, hold_s, cum_pnl_usd |
| `stat` (кожні 30 с) | лічильники повідомлень, fair_ready, armed, open_pos, pnl за стратегіями |
| `end` | підсумок |

Щоденний звіт paper: n філів (LONG/SHORT), середнє і медіана net_pct, CI90 за гаманцями і днями, частка мейкер-виходу, розподіл `visible_at_L_usd` і `wait_s`, частка філів від того ж гаманця, що дав тригер (зіставити `trig.taker` з тейкером принта-філу).

## 6. Реалізація

`a2_paper.py`: самодостатній paper-трейдер (stdlib + websocket-client), параметри з CLI, `--minutes N` обмежує сесію.
Для live потрібно замінити віртуальні заявки на HL `order` з `tif: "Alo"` (вхід, мейкер-вихід) і `tif: "Ioc"` (вихід, стоп), `modify` для перепегу, `cancel` при expire. Фактичні філи брати з `userFills` власного акаунта. Правило філу з розділу 3 тоді стає метрикою розбіжності paper vs live.
